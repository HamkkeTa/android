# 함께타 차량 앱 구현 메모

브랜치: `feature/carpool-dashboard-settlement`

## 구현 범위

- 와이어프레임의 그룹, 동승자 등록, 분담 규칙, 운행 요약, 장부 진입 화면을 Compose로 구현했습니다. 넓은 화면에서는 두 영역, 좁은 화면에서는 세로 배치입니다.
- 그룹 생성·선택, 동승자 등록·삭제, 그룹별 분담 규칙과 면제 대상을 차량 로컬 SharedPreferences에 저장합니다. 기존 고정 데모 그룹은 실제 로컬 저장소로 교체했습니다.
- 동승자는 이름·전화번호와 로컬 저장 동의를 입력하여 등록합니다. 전화번호는 10~11자리 숫자로 검증합니다. 저장되는 이름과 전화번호는 아직 서버로 전송하지 않습니다.
- BLE의 그룹원 검증이 같은 로컬 저장소를 사용합니다. 등록된 동승자 ID를 JOIN characteristic에 UTF-8로 쓰는 기존 프로토콜을 유지합니다. 일반 오디오 블루투스 페어링은 등록 절차가 아닙니다.
- BLE 서비스 등록 성공 후 광고하며, 광고 성공 시 세션을 Open으로 표시합니다. 광고 실패 시 자원을 정리합니다.
- 연결 해제 시 30초 하차 유예를 적용합니다. 그 안에 같은 동승자 ID가 재접속하면 이전 연결과 유예를 정리하고 탑승을 유지합니다. 이 값은 파일럿용 임시값입니다.
- 정산 엔진은 탑승자별 구간 합산, 운전자 포함/제외, 동승자 면제를 지원합니다. 먼저 전체 실비를 10원 단위로 반올림하고, 개인별 버림 후 남은 10원은 소수 잔여가 큰 순서로 배분합니다. 동률이면 운전자와 입력 순서로 배분합니다. 부담 가능한 동승자가 없는 구간은 운전자가 부담합니다.

## 실행 확인

1. 앱을 실행하고 BLE 권한을 허용합니다.
2. 실제 정차 상태에서 `정차 확인`를 체크합니다. 기본값은 편집 잠금입니다.
3. 그룹 생성 후 동승자의 이름·전화번호와 저장 동의를 입력합니다.
4. 동승자 앱/기존 PassengerSimulatorTest의 `memberId`에 화면의 연결 ID를 사용합니다. 기본 `member-1`은 더 이상 자동 등록되지 않습니다.
5. 등록된 기기가 접속하면 인원 표시가 바뀝니다. 접속자가 있으면 그룹·규칙 편집이 잠깁니다.
6. 분담 규칙을 변경하고 저장한 뒤 재실행하여 복원되는지 확인합니다.
7. 운행 요약에서는 예시 2개 구간, 3,300원의 분배를 확인합니다. 이는 실제 운행 데이터가 아닙니다.

검증 명령:

```powershell
.\gradlew.bat :app:ktlintCheck :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

## 아직 필요한 연동

- 차량 속도·시동·주행거리·좌석·도어·RSSI 검증은 구현되지 않았습니다. 정차 체크는 수동 확인이며 실제 주행 중 조작 차단을 보장하지 않습니다. 실제 차량 배포 전 차량 속도 기반 자동 잠금이 필요합니다.
- 현재 BLE 세션은 앱/기존 부팅 서비스 수명에 따릅니다. 시동 자동 시작·종료는 차량 SDK 이벤트 연동이 필요합니다.
- 동승자 ID는 인증 수단이 아닙니다. 실사용 전 승객 앱의 인증·기기 소유 확인 및 안전한 등록 흐름이 필요합니다. 자동 기기 검색과 동승자용 앱은 이번 변경 범위에 포함하지 않았습니다.
- 실측 거리·에너지 사용량 수집, 오프라인 운행 이벤트 보관·재전송, 실제 장부 누적, 유가/통행료 조회, 문자/알림톡·송금 링크·정산 상태 관리·월말 청구는 아직 미연동입니다. 미구현 기능을 성공한 것처럼 표시하거나 예시 금액을 실제 장부에 저장하지 않습니다.
- 백엔드/API 자격 증명과 차량 SDK 접근 환경을 확보한 후 위 연동을 이어갈 수 있습니다.

## 자동 검증 결과

- `:app:ktlintCheck`, `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug` 모두 통과했습니다.
- 단위 테스트 13개 통과(신규 정산 테스트 7개 포함).
- Lint는 오류 없이 완료되었으며 기존 API 호환성·중복 라벨·의존성 버전 경고가 남아 있습니다. 검사 비활성화 없이 BLE 생성자 선언을 단순화해 분석기 내부 오류를 해결했습니다.
- Pleos Connect v2.1.0 에뮬레이터에 APK를 설치하고 실행했습니다. 그룹/규칙/운행 요약 화면을 캡처해 확인했고, 그룹 생성 및 앱 재시작 후 복원을 확인했습니다. 실기기 간 BLE와 차량 센서 판정은 검증하지 않았습니다.
- 실행 화면 캡처는 로컬 `build/review/`에 있습니다(빌드 산출물로 Git 추적 제외).

## 참고 디자인 적용

- `design.png`의 함께타 서비스 영역을 기준으로 화면을 다시 구성했습니다. 다른 앱을 표현한 왼쪽 네모 패널은 앱 안에 구현하지 않았습니다.
- 녹색 사이드바를 제거하고, 큰 함께타 제목과 그룹·장부 상단 탭으로 변경했습니다. 운행 요약·분담 규칙은 상단 보조 메뉴에서 이동합니다.
- 흰 배경, 짙은 회색 글자·버튼, 회색 그룹 카드, 선택 카드의 테두리와 그림자, 멤버 패널의 둥근 테두리를 적용했습니다.
- 운전자·동승자는 원형 프로필로 구분하며, 같은 스타일을 운행 요약·규칙 설정·장부 빈 상태와 등록 창에도 적용했습니다.
- 연결 상태·정차 확인은 하단에 모았고, 동승자 연결 ID는 필요할 때 펼쳐 확인합니다. 실제 저장 데이터와 기존 편집 잠금을 유지합니다.
- 디자인 수정은 기능 구현 커밋 `34382fa` 이후의 별도 변경 사항입니다.
- 최종 디자인에서 `ktlintCheck`, 단위 테스트 13개, `lintDebug`, `assembleDebug`를 통과했습니다. Pleos 에뮬레이터에서 그룹·분담 규칙·운행 요약·장부·등록 창을 확인하고 정차 확인에 따른 버튼 활성화도 확인했습니다.
- 새 디자인 실행 캡처: `build/review/redesign/`.
